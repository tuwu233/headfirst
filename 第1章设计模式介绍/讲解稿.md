# 第1章｜设计模式介绍：把变化装进可替换的行为

[章节测验](练习题.html) · [Markdown 题稿](练习题.md)

> 学习目标：看见一段总在修改的分支代码时，能判断是否该把它拆成策略，并用 Python 写出可替换、可测试的行为。

建议用时：速读 8 分钟，运行与练习 10 分钟。先读第 1、3、5、8 节；需要动手时再展开完整示例。

## 1. 先记住这一句话

**策略模式：把完成同一件事的不同做法，做成可替换的行为，交给使用它的对象。**

鸭子不需要自己知道所有飞法。它只需要保存一个“飞行行为”，需要飞时调用它。今天用翅膀，明天换火箭，鸭子的调用代码不用跟着改。

这里的“算法”不只是排序或数学公式，也可以是运费规则、折扣规则、文件导出方式和重试策略。

## 2. 从书里的鸭子，看懂问题怎么产生

最初，所有鸭子都继承 `Duck`，共享游泳和叫声。后来给父类增加 `fly()`，橡皮鸭也继承了飞行，业务就错了。

| 尝试 | 为什么暂时有效 | 后续问题 |
| --- | --- | --- |
| 把飞行放进父类 | 所有子类立即复用 | 不该飞的鸭子也会飞，父类改动影响一大片 |
| 每个不飞的子类覆盖方法 | 修好了该子类 | 相同实现散落多处，新增子类容易忘记覆盖 |
| 只让会飞的鸭子实现接口 | 表达了能力差别 | 若每类仍各写一遍飞行代码，实现依旧重复 |
| 独立飞行行为，鸭子持有它 | 行为可以共享、组合和替换 | 多一层调用关系，需要清楚命名 |

**判断重点不是“继承坏不坏”，而是“变化的东西是不是和继承层次绑死了”。** 稳定的“是一种”关系仍可用继承；不同维度经常独立变化时，组合通常更合适。

## 3. 三条原则，直接对应三种动作

| 原则 | 白话 | 在本例中怎么做 |
| --- | --- | --- |
| 封装变化 | 把经常改的部分单独放 | 飞行、叫声独立于鸭子的其他行为 |
| 针对接口编程 | 依赖一种约定，不依赖某个具体实现 | 鸭子只要求行为“可调用且返回说明” |
| 优先组合而非继承 | 给对象安装能力 | `Duck` 持有飞行函数，而不是为了每种飞法新增鸭子子类 |

“接口”不等于必须写 Java 式接口类。在 Python 中，可以是函数签名、鸭子类型，也可以用 `Protocol` 描述约定。一个简单行为用函数就够了；需要保存复杂状态时，再考虑策略对象。

结构可以按一句话读出来：`调用者 → Duck.perform_fly() → 当前 fly_behavior()`。Duck 是使用策略的对象，`fly_with_wings`、`fly_no_way`、`fly_with_rocket` 是同一个算法家族。

## 4. 完整 Python 示例：运行时给模型鸭换飞法

同目录提供 [示例.py](示例.py)。使用 Python 3.10 或更高版本，无需安装第三方库；进入本章目录运行 `python 示例.py`。程序自带检查，失败时会抛出异常。

```python
from dataclasses import dataclass
from typing import Callable

Behavior = Callable[[], str]


def fly_with_wings() -> str:
    return "用翅膀飞行"


def fly_no_way() -> str:
    return "不会飞"


def fly_with_rocket() -> str:
    return "用火箭飞行"


def quack() -> str:
    return "嘎嘎叫"


def squeak() -> str:
    return "吱吱叫"


@dataclass
class Duck:
    name: str
    fly_behavior: Behavior
    quack_behavior: Behavior

    def perform_fly(self) -> str:
        return self.fly_behavior()

    def perform_quack(self) -> str:
        return self.quack_behavior()


def demo() -> None:
    mallard = Duck("绿头鸭", fly_with_wings, quack)
    model = Duck("模型鸭", fly_no_way, squeak)
    before = model.perform_fly()
    model.fly_behavior = fly_with_rocket
    after = model.perform_fly()

    actual = (mallard.perform_fly(), before, after, model.perform_quack())
    expected = ("用翅膀飞行", "不会飞", "用火箭飞行", "吱吱叫")
    if actual != expected:
        raise AssertionError(actual)
    print("绿头鸭：", actual[0], sep="")
    print("模型鸭换装前：", before, sep="")
    print("模型鸭换装后：", after, sep="")
    print("模型鸭叫声：", actual[3], sep="")
    print("自检通过")


if __name__ == "__main__":
    demo()
```

预期输出：

```text
绿头鸭：用翅膀飞行
模型鸭换装前：不会飞
模型鸭换装后：用火箭飞行
模型鸭叫声：吱吱叫
自检通过
```

## 5. 顺着调用走一遍，避免只会背类图

1. `Duck(..., fly_no_way, squeak)` 把两个函数交给模型鸭。注意传的是函数，不是 `fly_no_way()` 的结果。
2. `perform_fly()` 不检查鸭子品种，而是把工作交给当前飞行函数。这叫委托。
3. `model.fly_behavior = fly_with_rocket` 只替换飞行行为，不动叫声，也不修改 `Duck`。
4. 再次调用同一个 `perform_fly()`，结果就变了。这是组合带来的运行时弹性。

这些函数没有可变状态，所以多只鸭子可安全复用同一个函数。若策略对象保存计数、缓存等状态，复用之前要确认：这些状态到底应该共享，还是每只鸭子各有一份。

示例省去了鸭子继承树，保留策略的核心关系。书中飞行和叫声是两组策略；两者可以独立替换，避免为每种组合建立子类。

## 6. 把它搬到工作里：先找“可替换”的变化

例如订单支持普通快递、自提、加急快递。把运费计算写成相同签名的函数：`shipping(weight_kg) -> int`，返回整数“分”。订单对象接收其中一个函数，结算时直接调用。

新增“同城配送”时，增加一个函数，在创建订单的入口选择它；订单的结算流程不必改。**选择策略的分支仍可能存在，只是集中到了组装入口，策略模式不会让所有 `if` 消失。**

落地步骤：找变化点 → 约定统一输入输出 → 抽出两种实际存在的实现 → 把实现传给使用者 → 分别测试实现与委托关系。

| 值得用策略 | 先保持简单 |
| --- | --- |
| 同一行为有多种实现，且经常增加 | 只有一个稳定做法 |
| 多个业务对象重复一组判断 | 一个很短、清楚且稳定的分支 |
| 需要按配置或运行状态切换做法 | 不需要替换，也没有复用问题 |

## 7. 常见误区

- **“学了模式，就要把每个函数变成一个类。”** 不需要。Python 的函数本身就是对象。
- **“组合完全取代继承。”** 不是。这里拆的是易变行为，稳定的类型关系仍然可以保留。
- **“有接口，代码就自动解耦。”** 如果使用者仍写满具体类型判断，接口只是外壳。
- **“策略就是把任意代码拆开。”** 一组策略应解决同一个问题、遵守同一输入输出约定，才有可替换性。
- **“模式是现成库。”** 模式描述设计经验；库提供可调用实现。模式主要帮助你组织自己的代码，并让团队用共同词汇讨论设计。

## 8. 三分钟练习：给模型鸭增加滑翔

任务：新增 `glide()`，返回“滑翔”；让模型鸭先滑翔，再切回不会飞。禁止修改 `Duck.perform_fly()`。

<details>
<summary>查看参考答案与检查点</summary>

```python
def glide() -> str:
    return "滑翔"

model = Duck("模型鸭", glide, squeak)
assert model.perform_fly() == "滑翔"
model.fly_behavior = fly_no_way
assert model.perform_fly() == "不会飞"
```

只新增行为，并在组装处更换引用。若你去给 `perform_fly()` 加 `if name == ...`，就又把变化放回了使用者。

</details>

<details>
<summary>自测：为什么不直接写 Duck 的很多子类？</summary>

飞法与叫法可能独立变化。用子类表达所有组合，会让数量增加、相同实现重复；用两个行为引用，就能独立组合。只有真实类型差异、稳定的继承关系时，子类才更有意义。

</details>

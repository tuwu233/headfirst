换一种创建方式，观察“具体选择发生在哪里”。此演示对应下方三段工厂代码。

学习目标：清楚区分简单工厂、工厂方法与抽象工厂；面对新地区或新产品，能指出要修改的类，并选用最小的合适方案。

建议用时：速读 12 分钟，运行与练习 15 分钟。本章比前几章长，先读第 1、2、7 节建立区别，再看代码。

1. 先理解共同问题：谁负责创建对象

比萨店有稳定流程：接单 → 创建比萨 → 准备 → 烘焙 → 切片 → 装盒。变化的是卖哪些比萨、不同地区用什么原料。

如果订单方法到处写具体类型的创建代码，每次增加地区或调整原料，都可能碰到原本稳定的流程。工厂把“创建哪种对象、怎么创建”放到明确的位置，让使用者依赖产品约定。

工厂没有消灭具体对象，也没有消灭 new 或类调用；它把创建依赖集中起来。 Python 里的 CheesePizza() 与 Java 的 new CheesePizza() 在这个讨论里扮演同样角色。

2. 先分清三种写法，再背名字

方式 决定在哪里 核心机制 本书中的例子
简单工厂 一个函数或工厂对象的分支里 集中创建 按类型返回芝士或素食比萨
工厂方法 创建者子类的重写方法里 继承与多态 纽约店、芝加哥店各实现 createPizza
抽象工厂 传入的一组工厂实现里 组合与委托 纽约原料厂、芝加哥原料厂分别供应一整套原料

简单工厂是常用的创建惯用法，不属于 GoF 23 个模式中的独立模式，但它往往已经足够好。“代码里有个叫 factory 的函数”不代表使用了工厂方法模式。

工厂方法关注“某个创建步骤由哪个子类实现”；抽象工厂关注“一组需要相互匹配的产品由哪套工厂提供”。不能只靠返回几个对象来判断名称。

3. 书中的演进，为什么一步步引入工厂

第一步，把订单方法里的创建分支搬到简单工厂，订单仍负责烘焙等操作。

第二步，加盟店要保留当地风味，又要共享总部的制作流程。于是父类保留 order_pizza()，把 create_pizza() 交给地区子类实现。这是工厂方法。调用父类订单方法时，实际运行哪个创建方法，取决于店对象的真实类型。

第三步，不同地区还要供应匹配的面团和酱料。把这些创建方法组合成 IngredientFactory，比萨只向工厂要原料。这是抽象工厂。纽约厂返回薄饼与番茄酱，芝加哥厂返回厚饼与李子番茄酱。

两种模式可以同时出现：地区店用工厂方法创建比萨，再把当地原料工厂传给比萨。一个负责创建扩展点，一个负责原料家族。

4. 完整 Python 示例：一次运行，对照三种创建方式

同目录 示例.py，运行 python 示例.py，要求 Python 3.10+。流程与原料仅做内存模拟，不涉及真实烘焙。

为了把区别看清楚，三种写法放在同一文件中分别运行。两家原料工厂创建的是两类产品 Dough 和 Sauce；产品用数据表示口味，不必为每个口味再建子类。

PYTHON · 114 行
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import Protocol


@dataclass(frozen=True)
class Dough:
    name: str


@dataclass(frozen=True)
class Sauce:
    name: str


@dataclass
class Pizza:
    name: str
    dough: Dough
    sauce: Sauce
    steps: list[str] = field(default_factory=list)


# 1. 简单工厂：创建选择集中在一个函数中。
def simple_factory(kind: str) -> Pizza:
    if kind == "cheese":
        return Pizza("芝士比萨", Dough("普通面团"), Sauce("番茄酱"))
    if kind == "veggie":
        return Pizza("素食比萨", Dough("普通面团"), Sauce("番茄酱"))
    raise ValueError(f"不支持的比萨类型：{kind}")


# 2. 工厂方法：子类创建，父类使用产品完成共同流程。
class PizzaStore(ABC):
    def order_pizza(self) -> Pizza:
        pizza = self.create_pizza()
        pizza.steps.extend(["准备", "烘焙", "切片", "装盒"])
        return pizza

    @abstractmethod
    def create_pizza(self) -> Pizza:
        raise NotImplementedError


class NYStore(PizzaStore):
    def create_pizza(self) -> Pizza:
        return Pizza("纽约芝士比萨", Dough("薄饼面团"), Sauce("番茄酱"))


class ChicagoStore(PizzaStore):
    def create_pizza(self) -> Pizza:
        return Pizza("芝加哥芝士比萨", Dough("厚饼面团"), Sauce("李子番茄酱"))


# 3. 抽象工厂：客户向一个工厂索取相互匹配的产品家族。
class IngredientFactory(Protocol):
    def create_dough(self) -> Dough: ...
    def create_sauce(self) -> Sauce: ...


class NYIngredients:
    def create_dough(self) -> Dough:
        return Dough("薄饼面团")

    def create_sauce(self) -> Sauce:
        return Sauce("番茄酱")


class ChicagoIngredients:
    def create_dough(self) -> Dough:
        return Dough("厚饼面团")

    def create_sauce(self) -> Sauce:
        return Sauce("李子番茄酱")


def make_regional_pizza(factory: IngredientFactory) -> Pizza:
    return Pizza("地区比萨", factory.create_dough(), factory.create_sauce())


def demo() -> None:
    simple = simple_factory("cheese")
    veggie = simple_factory("veggie")
    ny = NYStore().order_pizza()
    chicago = ChicagoStore().order_pizza()
    family_ny = make_regional_pizza(NYIngredients())
    family_chicago = make_regional_pizza(ChicagoIngredients())
    checks = [
        simple.name == "芝士比萨",
        veggie.name == "素食比萨",
        ny.name == "纽约芝士比萨",
        chicago.name == "芝加哥芝士比萨",
        ny.steps == chicago.steps == ["准备", "烘焙", "切片", "装盒"],
        (family_ny.dough.name, family_ny.sauce.name) == ("薄饼面团", "番茄酱"),
        (family_chicago.dough.name, family_chicago.sauce.name)
        == ("厚饼面团", "李子番茄酱"),
    ]
    if not all(checks):
        raise AssertionError("工厂产品或流程不正确")
    try:
        simple_factory("unknown")
    except ValueError:
        pass
    else:
        raise AssertionError("未知类型应该明确失败")
    print("简单工厂：", simple.name, sep="")
    print("工厂方法：", ny.name, " / ", chicago.name, sep="")
    print("共同流程：", " → ".join(ny.steps), sep="")
    print("抽象工厂：", family_chicago.dough.name, " + ", family_chicago.sauce.name, sep="")
    print("自检通过")


if __name__ == "__main__":
    demo()

工厂方法示例每店只展示一种比萨，省去类型分支；真实菜单可以给 create_pizza(kind) 传类型，由各店分别决定支持什么，未知类型要明确报错。

5. 跟踪一次调用：哪个方法真的发生了替换

对于 NYStore().order_pizza()：先进入继承来的订单方法 → 调用 self.create_pizza() → 根据 self 的实际类型进入 NYStore 的实现 → 返回 Pizza → 订单方法执行共同流程。

父类知道的是 Pizza 的能力，不必分支判断纽约或芝加哥。子类负责创建，父类负责使用，这才是本例的工厂方法关系。

对于 make_regional_pizza(ChicagoIngredients())：函数持有工厂 → 调用 create_dough() 与 create_sauce() → 得到芝加哥的一套原料。更换传入工厂就能更换整套原料，不必修改制作函数。

抽象工厂把家族一致性的责任集中到具体工厂中，但不会自动验证一切。若芝加哥工厂写错返回了纽约酱料，仍然需要测试发现。

6. 依赖倒置：业务流程朝什么方向依赖

旧结构：订单流程 → 纽约具体比萨 / 芝加哥具体比萨 / 更多具体类。

改进后：订单流程依赖 Pizza 约定；原料使用者依赖 IngredientFactory 约定；具体实现满足这些约定。高层业务与底层细节围绕共同抽象配合，具体创建集中在工厂或程序组装入口。

这就是依赖倒置原则在本章的落点：重要流程依赖稳定的抽象，让容易变化的细节去适配它。

传入一个工厂对象是依赖注入的一种做法；依赖注入是“如何提供依赖”，依赖倒置是“代码依赖朝什么方向”，两者不要混为同一个概念。

不需要把每个 list()、dict() 或稳定的数据对象都包进工厂。只有创建规则、具体产品或家族真的变化时，才值得增加这一层。

7. 新需求来了，究竟改哪里

新需求 简单工厂 工厂方法 抽象工厂
新增一种菜单产品 通常修改集中分支 涉及该产品的具体店扩展创建逻辑 通常可由客户组合已有原料，不一定新增工厂接口
新增一个地区 通常扩大分支或配置 新增地区店子类，共同订单流程不变 新增地区原料工厂，实现完整家族
家族增加一种产品类别，如奶酪 按需求修改函数 按创建职责变化 要扩展工厂接口，并更新所有具体工厂及相关客户

抽象工厂擅长增加新家族，不擅长频繁增加家族里的产品类别。 这是一项真实代价，不是“设计越抽象就越好”。

选型顺序：一次简单创建直接调用类；创建分支重复时集中成函数；已经存在共享流程与子类扩展点时考虑工厂方法；需要替换整套相关产品时考虑抽象工厂。

Python 还可以把创建函数作为参数传入使用者，这是一种轻量的创建策略。没有子类重写关系时，不必硬把它叫作本书定义的工厂方法模式。

8. 五分钟练习：新增杭州原料家族

任务：提供“薄脆面团 + 葱香酱”；不得修改 make_regional_pizza()。然后回答：如果每套家族都新增奶酪，要改哪些地方？

class HangzhouIngredients:
    def create_dough(self) -> Dough:
        return Dough("薄脆面团")

    def create_sauce(self) -> Sauce:
        return Sauce("葱香酱")

pizza = make_regional_pizza(HangzhouIngredients())
assert pizza.dough.name == "薄脆面团"
assert pizza.sauce.name == "葱香酱"

新增家族只需新工厂并在入口选用它。新增奶酪这一产品类别，则要增加产品约定、create_cheese() 方法，并更新所有具体工厂和使用奶酪的客户。

自测：一个静态 create() 方法，是否就是工厂方法模式？

不一定。名称和 static 都不能决定模式。要看是否存在创建者抽象、子类重写创建步骤、共同流程通过多态调用该步骤。若只是函数里按字符串分支创建，更接近简单工厂。

9. 一分钟复习与原书定位

简单工厂：集中创建。工厂方法：子类决定创建。抽象工厂：对象提供一整套相关产品。先找变化在哪，再选结构。
